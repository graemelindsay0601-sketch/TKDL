# Workstream E2 — premium trophy integration guide

Owner: integration owner. E2 deliberately did **not** edit `features/career/identity.tsx`, shared Career CSS, the router/shell, apparel, sponsorship or any server module.

## What E2 provides

`artifacts/tkdl/src/features/career/trophies/` (import from `../trophies` or `@/features/career/trophies`):

| Export | Purpose |
|---|---|
| `PremiumTrophy({ trophy, size, engraving?, eventName?, decorative?, artwork? })` | Renders a premium design. `trophy` accepts existing content shapes: `{ id, name, designKey }`, `{ trophyId }` or `{ designId }`. Sizes `xs · sm · md · lg · hero`. `artwork`: `"auto"` (render; vector for catalogue families at `xs`), `"render"`, `"vector"`. Unknown ids render an explicit labelled fallback with `data-missing-trophy`. |
| `AwardPresentation({ event, size?, eventName?, persistedTrophyId?, policyVersion? })` | What a winner is shown receiving: premium trophy, plaque/medal or result-only marker. Exposes `data-design` and `data-design-source` (`EVENT_DESIGN · FAMILY · PERSISTED`). |
| `resolveAward(event, { version?, persistedTrophyId? })` | Policy lookup. Returns `trophyId` (catalogue family — unchanged from v1) **and** `designId` (what to draw). |
| `EVENT_DESIGNS_V2`, `FAMILY_IDS`, `EVENT_DESIGN_IDS`, `TROPHY_RENDERS`, `trophyRender(id)` | v2 allocation, design lists and render manifest. |
| `RecognitionMark`, `groupTrophyWins`, `TrophyContactSheet`, `TROPHY_ART`, `RECOGNITION_ART`, `trophyArt` | As before. |

Audit report (allocation, unique vs shared, every definition): `docs/career/e2-trophy-award-report.md`, regenerated by `node scripts/career-award-report.ts`.

## Integration rules (mandatory)

1. **Trophy artwork does not create playable events.** The manifest, renders and award policy are presentation only. No E2 module schedules, enables, registers or simulates an event; an event is playable only if Career scheduling generates it with an executable format. Six trophy-mapped definitions are authored but benched (see *Reachability*); having finished artwork does not change that.
2. **Only real recorded awards may appear in a Career trophy cabinet.** Cabinet, honours and profile rows must come from recorded results (`career_event_results` winners / existing cabinet rows), never from the catalogue, the award policy, the manifest or the contact sheet. A benched or cancelled event, a qualifier, a Q-School session, a weekly fixture or a result-only award never produces a cabinet trophy, and a stored `trophyId` alone never creates one.
3. **Special-format trophies are never substituted for unrelated championships.** `snooker-darts-cup`, `noughts-crosses-block`, `treble-triangles`, `cricket-scoreboard` and `league-shield-ring` are each allocated to exactly one event. The rule fallback never yields them, and `AwardPresentation` only accepts a catalogue *family* id as a persisted identity, so an event-design id can never be pushed onto another event (tested). Do not pick a design by name, look or "closest match".
4. **Event-aware resolution is mandatory for the unique designs.** The 12 event-specific designs are reachable only through `AwardPresentation` / `resolveAward` with the event's `definitionKey`. The `CareerTrophy` identity shim below can only resolve the 18 families (it matches catalogue `id`/`designKey`/`name`), so anywhere the event is known — cabinet, tournament hero/reveal, honours — must use `AwardPresentation`, not `PremiumTrophy` with a hand-picked id.
5. **Sporting results and saved trophy identities stay authoritative.** Results, titles, repeat-win counts, prize money, ranking points and qualification are never read from or changed by E2. A saved catalogue `trophyId` that differs from today's family is shown as recorded (`PERSISTED`); E2 never rewrites saves.

## Reachability through normal Career scheduling

Computed in `docs/career/e2-trophy-award-report.md` (section *Reachability*) from every catalogue version with the same `assessCapability` check that season generation uses; pinned by tests.

- **Scheduled (36 trophy events, 25 designs):** in the current catalogue (v5) with an executable format; can be won in a new Career (subject to each event's eligibility; NPCs win the rest).
- **Benched (6):** `snooker-darts-cup`, `noughts-and-crosses-trophy`, `national-cricket`, `national-halve-it` (non-X01 game types), `treble-out-trophy` (master/treble-out rule) and `regional-champions-league` (league structure). Season generation inserts them as `CANCELLED · INTENTIONALLY_BENCHED` (`calendar/engine.ts`); registration is refused with `UNSUPPORTED_FORMAT` (`calendar/service.ts`); `playWeek` never draws or plays them, so no result, prize or award can exist. They are benched in every catalogue version (v1–v5), so under the shipped scheduling code no win can be recorded for them in any save. `calendar/certification.ts` records why each is benched; capability refresh only re-assesses still-open X01 instances, and master-out is unsupported.
- **Legacy (2):** `double-start-grand-prix` (v1 saves only, replaced by The Double Crown) and `vault-masters` (v1–v2 saves only). Real wins can exist in those saves and display as recorded.
- `grand-slam-of-champions` was benched in v1–v2 (structure) and is scheduled from v3.

Their finished designs (`league-shield-ring`, `cricket-scoreboard`, `noughts-crosses-block`, `snooker-darts-cup`, `treble-triangles`) are kept as dormant assets. They appear only if a future workstream makes those formats executable and a winner is recorded; nothing in E2 does that.

## Designs and allocation (policy v2)

- **30 distinct designs** = the 18 catalogue families (ids unchanged) + 12 event-specific designs (`ec-continental-crest`, `wwc-crystal-flame`, `ywc-star-orb`, `junior-star-cup`, `open-finals-compass`, `awm-globe-cup`, `amateur-masters-tankard`, `league-shield-ring`, `snooker-darts-cup`, `treble-triangles`, `noughts-crosses-block`, `cricket-scoreboard`). All 30 are used.
- **25 events have a unique design** (5 of them benched — see above) (World Championship → Sovereign, Double Crown, Open, Grand Slam, Matchplay, Tour Finals, European, Women's World, Women's Masters, Youth World, Youth Masters, Foundation, Open International, Amateur World Masters, Amateur Masters, National Open, International Amateur Open, World Series Finals, Champions Masters, Regional Champions League, County Championship, Snooker Darts Cup, Treble Out, Noughts & Crosses, National Cricket).
- **Named shared groups:** National amateur championships (7 → Classic Silver Cup); International open series (6 → International Globe); Vault championship lineage (2 → Vault); Pro Circuit tour rounds (1 → Championship Plate, kept modest per the approved rule); Local & format championships (Town Open, National Halve-It → Wood & Silver Shield). `double-start-grand-prix` is a retired v1 major kept as recorded (HISTORIC).
- Weekly fixtures, ordinary tour/series rounds, qualifiers and Q-School are unchanged: result-only or plaque, never a trophy.

## Historical save compatibility

| Saved situation | What is shown | Why |
|---|---|---|
| Win recorded with the event's catalogue `trophyId` (all saves to date) | v2 event design for that event, e.g. Amateur Masters → Tankard | Same event, same `trophyId`; only the artwork for that event changed. `data-design-source="EVENT_DESIGN"`. |
| Stored `trophyId` (a catalogue family) differs from today's family | The stored identity, as recorded | Never reinterpreted. `designSource: "PERSISTED"`. |
| Persisted id is an event-design id (cannot occur from saved content) | The event's own design | Rejected as a stored identity, so no cross-event substitution. |
| Stored `trophyId` unknown to the manifest | The event's policy design | Avoids a broken image; identity text unchanged. |
| Stored `trophyId` on a weekly / Q-School / qualifier result | Result-only marker | A stored id alone never creates a trophy. |
| Caller wants the pre-v2 look | `policyVersion={1}` → catalogue family | v1 resolution is kept and tested. |

Award type, kind, `trophyId`, inscription, results, titles, repeat-win counts, prize money and ranking points are identical under v1 and v2 for every one of the 95 definitions (tested). No save migration is needed. If the integration owner prefers wins recorded before v2 to keep the family art, pass `policyVersion={1}` for those records; nothing else changes.

## Artwork pipeline (honest limits)

- Renders: `public/assets/career-trophies/render/<id>.webp` (720×960, transparent, ~16–55 KB each, 992 KB total) + `render-manifest.json` / `render-manifest.ts` (projected plate rectangle per design, used to place the engraving).
- Produced by `scripts/trophy-render/` with three.js `MeshPhysicalMaterial` (metalness/roughness, clearcoat, anisotropy, iridescence) under a procedural studio environment, ACES tone-mapped, 2× supersampled, in headless Chromium (WebGL2 via SwiftShader). three.js is a build-time tool only — it is not in the app bundle.
- These are **real-time physically based renders, not path-traced or photographic**: no true caustics, refraction or ray-traced reflections. Glass is a thin-glass approximation (transparent material + edge lines), not refraction. Geometry is procedural (lathe/extrude/tube), so fine chasing and engraving are suggested rather than modelled.
- Regenerate: `cd artifacts/tkdl && node scripts/trophy-render/render-trophies.mjs [ids…]` (set `THREE_DIR` to a local `three@0.170.0` to work offline; otherwise it installs into `node_modules/.cache/trophy-render`). Renders are visually stable but byte determinism across machines is not guaranteed or tested; tests pin format, size, coverage, uniqueness and plate geometry instead.
- The 18 vector SVGs (`scripts/build-career-trophies.mjs`, deterministic) remain for `xs` and as the image-load fallback.

## Integration steps

1. **Replace the shared renderer** in `features/career/identity.tsx`:
   ```tsx
   import { PremiumTrophy, TROPHY_ART, type TrophySize } from "./trophies";
   export function CareerTrophy({ name, design = "", id, size = "md", engraving }: { name: string; design?: string; id?: string; size?: TrophySize; engraving?: string }) {
     const known = Object.values(TROPHY_ART).find(a => a.id === id || a.designKey === design || a.name === name);
     return <PremiumTrophy trophy={{ id: known?.id ?? id ?? null, name }} size={size} engraving={engraving} />;
   }
   ```
   Prefer `AwardPresentation` wherever the event is known, so event-specific designs appear.
2. **Trophy cabinet** (`world.tsx` `TrophyPage`, `legacy/components.tsx` `Shelf`/`HonoursShelf`): render `AwardPresentation event={{ definitionKey: row.canonicalEventId, circuit: row.circuit, classification: row.classification }} persistedTrophyId={row.trophy?.id}`; group with `groupTrophyWins`. `RESULT_ONLY` rows stay listed as wins.
3. **Tournament hero, arrival & completion** (`tournament/components.tsx`): `AwardPresentation event={…v.event} persistedTrophyId={v.event.content?.trophyId} size="lg"`; champion reveal `size="hero"` inside `className="ct-reveal"` (respects reduced motion).
4. **NPC honours, season reviews, Darts World honours, A Career Remembered**: `AwardPresentation size="sm"`. Never derive a trophy from a name.
5. **CSS**: `trophies.css` is imported by the component module; no global CSS change needed.
